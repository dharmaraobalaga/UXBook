### 2 · Funnel
Funnel – where in the journey does the user drop off?

Area: Product Analytics + Growth

What is a Funnel?

A funnel is the sequence of stages a user passes through in a product until they complete a goal. At each stage some users may leave instead of moving forward.

You can think of it as the path of conversion stages (a Conversion Funnel).

Example: Food Delivery App

Suppose 10,000 people opened the app in a day.

@@FIG2

Food Ordering Conversion Funnel:

App Open	10,000 users · 100%
Restaurant Viewed	7,000 users · 70%
Food Added to Cart	4,000 users · 40%
Checkout Started	2,500 users · 25%
Payment Completed	2,000 users · 20%

Illustrative data only – numbers used just for an example.

Here:
- 10,000 people opened the app.
- 7,000 viewed a restaurant.
- 4,000 added food to the cart.
- 2,500 started checkout.
- 2,000 completed payment.

Overall conversion rate:

Conversion Rate = (2,000 ÷ 10,000) × 100 = 20%

So of the 10,000 people who opened the app, only 2,000 completed an order.

PM, PD, UX and UI responsibilities in a funnel

Role	Responsibility in the funnel
PM	Setting business conversion targets
PD	Improving the overall funnel experience
UX	Identifying user friction at each stage
UI	Improving buttons, forms, clarity and visual hierarchy

Why use a funnel?

- Where are the most people leaving?
- At which stage is the problem?
- Which change would increase conversion?
- Which feature should get priority?

Important funnel terms

- Conversion: a user completing the desired action.
- Drop-off: stopping instead of moving from one stage to the next.
- Conversion Rate: the percentage of users who completed the target action.
- Abandonment: leaving a process without completing it.

### 3 · Loop
Loop – how do we get users to use the product again and again?

Area: Product Growth + Engagement + Retention

What is a Loop?

In a loop, an action produces a result, and that result helps start the same process again.

You can think of it as a process that goes round like a wheel.

In a funnel the user moves forward from one stage to the next. In a loop, the result of an action becomes an input to the same system again and contributes to more actions or growth.

Example: Food Delivery Referral Loop

Suppose a customer recommends the food delivery app to a friend.

@@FIG3

1. Existing User – a customer using the app
2. Referral – sends the app link to a friend
3. New User – the friend downloads the app
4. First Order – the new customer places a first order
5. Reward – a referral reward is given
6. More Referrals – the new customer may recommend the app to someone else

Loop repeats – back to the first stage.

In this process, existing users are the ones helping new users arrive.

Funnel vs Loop – the real difference

Funnel	Loop
A journey from one stage to the next	A process that starts again
Identifies where the drop-off is	Shows how growth or repeat engagement happens
Focus on conversion	Focus on repeated value and growth
Usually one specific journey	A system that keeps going round

Example: a customer ordering food is a funnel. That customer inviting a friend after ordering and bringing in a new customer is a growth loop.

These two are not alternatives to each other. A product may need both.

### 4 · Types of loop
Important types of loop in a product

A. Growth Loop:

A process in which users' actions create new users or business growth.

Example:

- Existing user invites a friend.
- Friend joins.
- Friend uses the product.
- Friend invites others.

HMW: How might we encourage existing users to invite new users?

B. Engagement Loop:

Engagement grows as a user repeats a valuable action in the product again and again.

Example – Food Delivery:

- User opens app.
- Sees personalised recommendations.
- Finds a suitable restaurant.
- Places an order.
- Gets a useful experience.
- Returns when they need food again.

HMW: How might we make every visit more valuable for users?

C. Feedback Loop:

A process of collecting user feedback, improving the product based on it, and checking the results again.

Example:

1. User gives feedback.
2. Team analyses feedback.
3. Design improvements are made.
4. Updated product is released.
5. User behaviour is measured.
6. More feedback is collected.

HMW: How might we continuously improve the product based on user feedback?

D. Build–Measure–Learn Loop:

This is the well-known learning loop from Lean Startup.

Stage	Meaning	Example
Build	Making the solution	Simplified checkout prototype
Measure	Measuring the result	Usability test, completion rate
Learn	Understanding what was learned	Users still struggle with address selection

Then another design iteration starts based on what was learned.

E. Habit Loop:

A model that helps a user repeat an action as a habit.

The well-known Hook Model has four parts:
1. Trigger: the cue that starts the action.
2. Action: what the user does.
3. Variable Reward: a reward with surprise or variety.
4. Investment: the time, data or effort the user puts into the product.

Example – Learning App:

- Trigger: Daily learning reminder.
- Action: User completes a lesson.
- Variable Reward: Progress feedback or achievement.
- Investment: User saves learning progress and preferences.

Use this in a way that gives the user real value – not to push unnecessary notifications or compulsive usage.

F. Flywheel:

A flywheel is a business model in which a good customer experience becomes fuel for the next good results.

Example:

Better Product Experience → Customer Satisfaction → Repeat Usage → Positive Reviews & Referrals → More Customers → More Business Resources → Better Product Experience.

A growth loop shows one specific growth mechanism. A flywheel usually shows a system across the whole business or product ecosystem in which positive results strengthen one another.

### 5 · AARRR – Pirate Metrics
AARRR – Pirate Metrics Framework

Area: Product Management + Growth Analytics

AARRR is a framework for understanding product growth in five important stages.

Letter	Full Form	Meaning
A	Acquisition	Getting users
A	Activation	The user experiencing first value
R	Retention	Users coming back
R	Referral	Users recommending it to others
R	Revenue	Earning revenue

Food Delivery Example

1. Acquisition

How does the user find out about the app?

Metrics:
- Website visitors
- App downloads
- Sign-ups
- Customer Acquisition Cost (CAC)

2. Activation

Did the user get value from the product the first time?

Metrics:
- First order completed
- Time to first order
- First successful transaction

3. Retention

Is the user coming back?

Metrics:
- Repeat orders
- Weekly Active Users
- Monthly Active Users
- Retention Rate

4. Referral

Is the user recommending the app to others?

Metrics:
- Referral invitations
- Successful referrals
- Referral conversion rate

5. Revenue

Is the product generating revenue?

Metrics:
- Average Order Value
- Revenue per Customer
- Gross Revenue
- Repeat Purchase Revenue

AARRR can be analysed as a funnel. It can also be combined with growth loops.

### 6 · HEART Framework
HEART Framework – how do we measure the UX experience?

Area: UX Research + Product Design

HEART is a UX measurement framework proposed at Google Research. It is used to measure how good an experience a product or feature gives users.

Letter	Full Form	Meaning
H	Happiness	User satisfaction
E	Engagement	How much the user takes part
A	Adoption	Uptake of a new feature
R	Retention	The user coming back
T	Task Success	Completing the task successfully

Food Delivery Example

Category	Question	Example Metric
Happiness	Is the user happy?	CSAT, satisfaction survey
Engagement	How often do they use it?	Sessions, feature usage
Adoption	Are people using the new feature?	Feature adoption rate
Retention	Are they coming back?	30-day retention
Task Success	Are they completing orders easily?	Task completion rate

Why does a UX Designer need HEART?

You can't call it good UX just because the UI looks beautiful.

For example: a new checkout design may look very attractive, but if users can't complete their order, the design is not successful.

HEART is used to try to measure UX quality.

HMW Example:

How might we improve task success and user satisfaction during checkout?

### 7 · JTBD – Jobs To Be Done
JTBD – Jobs To Be Done

Area: Product Discovery + UX Strategy

What is JTBD?

Jobs To Be Done is a way of understanding why a user uses a product to get the outcome they need.

Usually we ask: who is the user?

In JTBD we ask another important question:

What job is the user trying to get done?

That is: which task does the user want to complete, and what outcome do they want to achieve?

Example – Food Delivery App

Usually:

"User wants to order food."

From a JTBD angle:

"User wants to get a reliable meal quickly without spending time cooking or travelling."

JTBD looks at three kinds of need:

Type	Meaning	Example
Functional Job	The actual task to be done	Order food
Emotional Job	How they want to feel	Feel confident
Social Job	How they want to appear to others	Be a thoughtful host

Uses of JTBD

- Finding new product ideas.
- Understanding user needs.
- Understanding the problem more deeply than competitor analysis.
- Prioritising product features.
- Creating HMW questions.

HMW Example:

How might we help busy professionals get a reliable meal without spending time planning and preparing food?

### 8 · Double Diamond
Double Diamond – Design Process Framework

Area: Design Strategy + UX Process

The Double Diamond is a design process model popularised by the Design Council.

It has four main stages.

Stage	Meaning	In short
Discover	Explore the problem	Looking at the problem broadly
Define	Identify the right problem	Defining the real problem
Develop	Explore possible solutions	Exploring many solutions
Deliver	Test and deliver solutions	Testing and delivering the solution

@@FIG4

First diamond – Problem Space:

Discover: talking to users, research, observation.

Define: identifying the real problem from the research, writing the problem statement and HMW.

Second diamond – Solution Space:

Develop: brainstorming, sketching, wireframes, prototype.

Deliver: usability testing, iterations, development, release.

Divergent & Convergent Thinking in it:

- Divergent Thinking: thinking broadly about many possibilities.
- Convergent Thinking: choosing the right one and moving ahead.

Example:

In Discover we identify many user problems. In Define we choose the important problem. In Develop we think of many design solutions. In Deliver we test and implement the right solution.

Where does HMW come in? Usually at the end of Define, showing the way into the start of Develop.

### 9 · Design Thinking
Design Thinking – five stages

Area: Product Discovery + UX Design

Stage	Meaning	Example
Empathize	Understanding the user	User Interviews
Define	Defining the problem	Problem Statement
Ideate	Solution ideas	Brainstorming, HMW
Prototype	Making a model	Wireframes, Figma Prototype
Test	Testing with users	Usability Testing

Double Diamond and Design Thinking are both ways to understand a problem and test a solution. But their structure and stage descriptions are not the same.

### 10 · Prioritisation Frameworks
Prioritisation Frameworks – what should be done first?

Area: Product Management + Product Design

Suppose a product has 50 features. We can't develop them all at once, so we must decide which feature gets priority first.

A. RICE Framework:

RICE has four parts:

Letter	Full Form	Meaning
R	Reach	How many users will it affect?
I	Impact	How big will the impact be?
C	Confidence	How confident are we in our estimate?
E	Effort	How much effort does it need?

Formula:

RICE = (Reach × Impact × Confidence) ÷ Effort

Example:

Feature	Reach	Impact	Confidence	Effort
Simplified Checkout	1000	3	80%	4
Dark Mode	500	1	90%	3

You can calculate a RICE score from these values and compare features. These scores are only an example.

B. MoSCoW Framework:

Category	Meaning	Example
Must Have	Essential	Payment functionality
Should Have	Very important	Order tracking
Could Have	Nice to have	Personalised themes
Won't Have (for now)	Not doing it now	Advanced animations

C. Impact vs Effort Matrix:

Category	Meaning
High Impact + Low Effort	Quick Wins
High Impact + High Effort	Major Projects
Low Impact + Low Effort	Fill-ins
Low Impact + High Effort	Avoid or Deprioritise

These frameworks are most useful to PMs. Product Designers also use them to prioritise design tasks, UX improvements and design debt.

### 11 · Product Metrics
Product Metrics – which other terms should you know?

These are not frameworks but important metrics that measure product performance.

Term	Meaning	Example
KPI	Key performance indicator	Order Conversion Rate
North Star Metric	The metric that reflects the main value the product delivers	Successful Orders per Week
DAU	Daily Active Users	Users who use it every day
WAU	Weekly Active Users	Users who use it each week
MAU	Monthly Active Users	Users who use it each month
Retention Rate	Percentage of users who come back	30-day retention
Churn Rate	The rate at which users or customers are lost	Subscription cancellations
Conversion Rate	Percentage who completed the target action	Completed Orders
Drop-off Rate	Percentage who stop midway	Checkout abandonment
CAC	Customer Acquisition Cost	The cost of getting one new customer
LTV	Lifetime Value	The value a customer brings over time
AOV	Average Order Value	Average order value
Cohort Analysis	Analysing a group of users with a shared trait	November sign-up users

What is Cohort Analysis?

Comparing, over time, the behaviour of users grouped by the same time period or the same trait.

Example:

- Users who signed up in January.
- Users who signed up in February.
- Users who signed up in March.

You look at which of these three groups keeps using the app longer and which leaves quickly.

What is A/B Testing?

Making two versions of a design or feature, showing them to different user groups, and comparing the results.

Example:

- Version A: one large CTA button at checkout.
- Version B: a sticky bottom CTA button.

Which version gets more people to complete their order is tested through proper experiment design.

This helps measure the impact of UI and UX changes. But to say the result came from the change, you must also consider experiment design, sample size and statistical significance.
