26. Task Flow vs User Flow

తెలుగు వివరణ
Task Flow (పని పూర్తిచేసే క్రమం):

ఒక వినియోగదారుడు నిర్దిష్టమైన పనిని పూర్తి చేయడానికి అనుసరించే వరుస దశలను Task Flow అంటారు.

ఇందులో సాధారణంగా ఒక నిర్దిష్ట లక్ష్యాన్ని చేరుకోవడానికి అవసరమైన స్టెప్స్ మాత్రమే ఉంటాయి.

ఉదాహరణకు: ఒక యూజర్ యాప్‌లో Login అవ్వడం.

User Flow (వినియోగదారుడి ప్రయాణ మార్గం):

ఒక వినియోగదారుడు తన లక్ష్యాన్ని చేరుకోవడానికి ప్రొ డక్ట్‌లో అనుసరించే పూర్తి మార్గా న్ని User Flow అంటారు.

ఇందులో వివిధ స్క్రీన్లు , యూజర్ నిర్ణయాలు, ప్రత్యామ్నాయ మార్గా లు మరియు సిస్టమ్ స్పందనలు ఉంటాయి.

English Definitions

     Task Flow: A linear sequence of steps a user follows to complete a specific task within a product.
     User Flow: A visual representation of the different paths, screens, decisions and interactions users follow to achieve a goal within a product.


Key Differences

Task Flow                                   User Flow

Focuses on one specific task                Focuses on the complete interaction path toward a goal

Usually linear                              Can contain multiple branches

Shows task steps                            Shows screens, decisions and interactions

Simpler representation                      More comprehensive representation

Example: Login process                      Example: Different ways to access an account


Practical Example – Banking App

Task Flow: Money Transfer

                                                                                   Login



                                                                             Select Beneficiary




                                                                               Enter Amount




                                                                             Confirm Transfer
                                                                            Transaction Successful

                                                                             Simple linear task flow


User Flow: Money Transfer


                                                                             Open Banking App



                                                                                      Login



                                                                          Choose Transfer Method

                                  Existing Beneficiary                                                                   New Beneficiary


                                     Select Account                                                                        Add Account




                                                                          Enter Amount & Confirm



                                                                             Transfer Successful

                                                                   Illustrative user flow with alternative paths



Interview Answer (English)

"Task Flow represents the steps required to complete a specific task, usually in a straightforward sequence. User Flow represents the broader interaction
paths, including screens, decisions and alternative scenarios. For example, a money transfer task flow shows the basic transfer steps, while a user flow
also considers whether the beneficiary already exists or needs to be added."




27. User Flow vs User Journey

తెలుగు వివరణ
User Flow:

ఒక వినియోగదారుడు యాప్ లేదా వెబ్‌సైట్‌లో ఒక లక్ష్యాన్ని సాధించడానికి ఏ స్క్రీన్ నుంచి ఏ స్క్రీన్‌కు వెళ్తా డు? ఎక్కడ క్లిక్ చేస్తా డు? ఏ నిర్ణయాలు తీసుకుంటాడు? అనే విషయాలను
చూపిస్తుంది.

ఇది ప్రధానంగా Digital Product Interaction పై దృష్టి పెడుతుంది.

User Journey:

ఒక వినియోగదారుడు ఒక లక్ష్యాన్ని సాధించే క్రమంలో ఎదుర్కొనే మొత్తం అనుభవాన్ని చూపిస్తుంది.

ఇందులో Digital Interactions మాత్రమే కాకుండా భావోద్వేగాలు, అంచనాలు, సమస్యలు, Touchpoints మరియు Pain Points కూడా ఉంటాయి.

English Definitions

     User Flow: A visual representation of the screens, actions and decision points users navigate through to complete a goal in a digital product.
     User Journey: A broader representation of a user's experience across stages, including actions, thoughts, emotions, touchpoints and pain points.


Key Differences

User Flow                                                User Journey

Focuses on product interactions                          Focuses on overall experience

Shows screens and navigation                             Shows stages and touchpoints

Includes decisions and actions                           Includes emotions and expectations

Usually product-specific                                 Can include online and offline experiences

Used to improve navigation                               Used to improve the overall experience
Practical Example – Online Shopping

User Flow:

Open App → Search Product → Product Details → Add to Cart → Checkout → Payment → Order Confirmation.

User Journey:

Stage                                User Experience                                           Emotion

Need Identification                  Wants to buy a mobile                                     Interested

Product Discovery                    Searches different models                                 Curious

Comparison                           Compares features and prices                              Confused

Purchase                             Completes payment                                         Confident

Delivery                             Tracks the order                                          Excited

Post-purchase                        Receives product                                          Satisfied


Interview Answer (English)

"User Flow focuses on how users navigate through a digital product to complete a specific goal. User Journey captures the broader experience across
different stages and touchpoints, including user actions, thoughts, emotions and pain points. I use user flows to improve product interactions and journey
maps to identify experience gaps across the entire lifecycle."




28. User Journey vs Customer Journey

తెలుగు వివరణ
ఈ రెండు పదాలు చాలా దగ్గరగా ఉంటాయి. కానీ వాటి పరిధిలో తేడా ఉంటుంది.

User Journey:

ఒక వ్యక్తి ప్రొ డక్ట్ లేదా సర్వీస్‌ను ఉపయోగించే సమయంలో ఎదుర్కొనే అనుభవాలపై దృష్టి పెడుతుంది.

Customer Journey:

ఒక వ్యక్తి మొదటిసారి ఒక బ్రాండ్ గురించి తెలుసుకున్నప్పటి నుంచి కొనుగోలు చేయడం, ఉపయోగించడం, సపోర్ట్ పొందడం, మళ్లీ కొనుగోలు చేయడం వరకు మొత్తం ప్రయాణాన్ని
వివరిస్తుంది.

Customer Journey సాధారణంగా Marketing, Sales, Purchase, Support వంటి విస్తృతమైన దశలను కలిగి ఉంటుంది.


English Definitions

     User Journey: A representation of the experiences and interactions a user has while using a product or service to achieve a goal.
     Customer Journey: A representation of the complete customer lifecycle across brand awareness, consideration, purchase, service and loyalty
     touchpoints.


Key Differences

User Journey                                  Customer Journey

Focuses on product usage                      Focuses on the complete customer lifecycle

User experience oriented                      Customer relationship oriented

Covers interaction stages                     Covers marketing, sales and service stages

Used by UX/Product teams                      Used by UX, Marketing and Business teams

Often narrower in scope                       Usually broader in scope


Practical Example – Food Delivery App

User Journey:

Open App → Search Restaurant → Select Food → Place Order → Track Delivery → Rate Food.

Customer Journey:
     Awareness: Sees an advertisement.
     Consideration: Compares food delivery platforms.
     Acquisition: Downloads the app and registers.
     Purchase: Places the first order.
     Retention: Uses the app regularly.
     Loyalty: Recommends the app to friends.


Interview Answer (English)

"User Journey focuses on the user's experience while interacting with a particular product or service. Customer Journey covers the broader relationship
between a customer and a brand, including awareness, acquisition, purchase, support and loyalty. User Journey is often a part of the overall Customer
Journey."




29. Sitemap vs Information Architecture

తెలుగు వివరణ
Sitemap (సైట్‌మ్యాప్):

ఒక వెబ్‌సైట్‌లోని అన్ని పేజీలు ఏ క్రమంలో ఉన్నాయి? వాటి మధ్య సంబంధం ఏమిటి? అనే విషయాలను Hierarchical Structure రూపంలో చూపిస్తుంది.

ఇది వెబ్‌సైట్ పేజీల మ్యాప్ లాంటిది.

Information Architecture – IA (సమాచార నిర్మాణం):

ఒక డిజిటల్ ప్రొ డక్ట్‌లో సమాచారాన్ని ఎలా క్రమబద్ధీకరించాలి? ఏ కంటెంట్ ఎక్కడ ఉండాలి? ఎలా వర్గీకరించాలి? యూజర్లు సులభంగా ఎలా కనుగొనాలి? అనే విషయాలను నిర్ణయించే
విధానం.

IA అనేది Sitemap కంటే విస్తృతమైన కాన్సెప్ట్ .


English Definitions

     Sitemap: A visual representation of a website's pages and their hierarchical relationships.
     Information Architecture: The practice of organising, structuring and labelling information so users can easily find and understand content.


Key Differences

Sitemap                                         Information Architecture

Shows page hierarchy                            Defines overall information structure

Focuses on pages                                Focuses on content, labels and relationships

A visual deliverable                            A broader design discipline

Helps plan website structure                    Helps improve findability and navigation

One part of IA documentation                    Includes sitemap, taxonomy and navigation


Practical Example – E-commerce Website

                                                                                Home



                          Products                                              Offers                                         Account

                         Categories                                              Deals                                          Orders

                                                                      Illustrative website sitemap


Information Architecture:

     Group products into meaningful categories.
     Use understandable labels.
     Organise product filters.
     Define navigation hierarchy.
     Ensure users can find products easily.
Interview Answer (English)

"Information Architecture is the broader discipline of organising and structuring content to make it easy to find and understand. A sitemap is a visual
deliverable that represents the hierarchy and relationships between website pages. In simple terms, a sitemap is one of the outputs of Information
Architecture."




30. Sitemap vs Navigation Structure

తెలుగు వివరణ
Sitemap:

వెబ్‌సైట్‌లో ఉన్న అన్ని పేజీలు మరియు వాటి Hierarchy ను చూపిస్తుంది. ఒక పేజీకి ఏ పేజీలు Child Pages గా ఉన్నాయో తెలుసుకోవచ్చు.

Navigation Structure:

వినియోగదారులు ఆ పేజీల మధ్య ఎలా ప్రయాణించాలి? Main Menu, Submenu, Tabs, Breadcrumbs వంటి Navigation Elements ఎలా పనిచేయాలి? అనే విషయాలను
నిర్ణయిస్తుంది.

English Definitions

     Sitemap: A structural map of website pages and their hierarchical relationships.
     Navigation Structure: The system of menus, links and controls that allows users to move between different sections of a product.


Key Differences

Sitemap                                                                   Navigation Structure

Represents all pages                                                      Represents how users navigate

Shows hierarchy                                                           Shows navigation paths

Mainly a planning artifact                                                Part of the interaction design

Includes pages not always directly accessible in menus                    Focuses on navigation access

Helps define content structure                                            Helps users move through content


Practical Example – Corporate Website

Sitemap:

Home → About Us → Services → Portfolio → Contact.

Navigation Structure:

     Header navigation.
     Dropdown menu under Services.
     Portfolio category tabs.
     Footer links.
     Breadcrumbs for internal pages.


Interview Answer (English)

"A sitemap defines the hierarchy of pages within a website, whereas navigation structure defines how users move between those pages through menus,
links and other navigation elements. The sitemap helps organise content, while navigation makes that content accessible."




31. Card Sorting vs Tree Testing

తెలుగు వివరణ
Card Sorting (కార్డు లను వర్గీకరించడం):

వినియోగదారులు ఒక వెబ్‌సైట్ లేదా యాప్‌లోని సమాచారాన్ని ఎలా వర్గీకరించాలని అనుకుంటున్నారు? ఏ అంశాలను ఒకే గ్రూ ప్‌లో ఉంచాలని భావిస్తు న్నారు? అనే విషయాలను
తెలుసుకునే UX Research Method.

ఇందులో కంటెంట్ పేర్లను కార్డు ల రూపంలో ఇచ్చి యూజర్లతో గ్రూ పులుగా విభజింపజేస్తా రు.
మూడు ప్రధాన రకాలు:
     Open Card Sorting – యూజర్లు తమ సొంత కేటగిరీలను సృష్టిస్తా రు.
     Closed Card Sorting – ముందుగా ఇచ్చిన కేటగిరీల్లో కార్డు లను అమర్చుతారు.
     Hybrid Card Sorting – ముందుగా ఇచ్చిన కేటగిరీలను ఉపయోగించవచ్చు లేదా కొత్త కేటగిరీలను సృష్టించవచ్చు .

Tree Testing (నావిగేషన్ నిర్మాణాన్ని పరీక్షించడం):

వెబ్‌సైట్ లేదా యాప్‌లోని కంటెంట్‌ను వినియోగదారులు సరైన కేటగిరీలో సులభంగా కనుగొనగలుగుతున్నారా? అనే విషయాన్ని పరీక్షించడం.

ఇందులో Visual Design లేకుండా కేవలం Text-Based Navigation Hierarchy ఉపయోగిస్తా రు.

English Definitions

     Card Sorting: A research technique used to understand how users naturally group and categorise information.
     Tree Testing: A usability research method used to evaluate whether users can find information within a proposed navigation hierarchy.


Key Differences

Card Sorting                                              Tree Testing

Helps organise content                                    Tests content findability

Explores user mental models                               Evaluates navigation structure

Users group information                                   Users locate specific information

Used to develop IA                                        Used to validate IA

Input for navigation design                               Evaluation of navigation design


Practical Example – E-commerce Website

Card Sorting:

Give users cards such as:

     Mobile Phones
     Laptops
     Headphones
     Smart Watches
     Chargers
     Speakers

Ask them to group the cards into categories.

Tree Testing:

Give users the task:

"Find wireless headphones under ₹2,000."

Observe whether they navigate through the correct category and find the information.


Interview Answer (English)

"Card Sorting helps us understand how users naturally organise and categorise information, whereas Tree Testing evaluates whether users can find
information within a proposed information architecture. I use Card Sorting to create or improve navigation structures and Tree Testing to validate their
effectiveness."




32. Open Card Sorting vs Closed Card Sorting

తెలుగు వివరణ
Open Card Sorting:

యూజర్లకు కంటెంట్ కార్డు లను ఇచ్చి, వాటిని తమకు నచ్చిన విధంగా గ్రూ పులుగా విభజించి, ప్రతి గ్రూ ప్‌కు తగిన పేరును పెట్టమని అడుగుతాం.

ఇక్కడ కేటగిరీలను ముందుగా నిర్ణయించము.

Closed Card Sorting:
యూజర్లకు కార్డు లతో పాటు ముందుగానే కొన్ని కేటగిరీలను ఇస్తాం. వారు ప్రతి కార్డు ను సరైన కేటగిరీలో ఉంచాలి.

ఇక్కడ కేటగిరీలు ముందుగానే నిర్ణయించబడి ఉంటాయి.

English Definitions

     Open Card Sorting: A technique where participants create their own categories and organise content cards into those groups.
     Closed Card Sorting: A technique where participants organise content cards into predefined categories.


Key Differences

Open Card Sorting                                                  Closed Card Sorting

Categories are created by users                                    Categories are predefined

Explores user mental models                                        Validates existing categories

More exploratory                                                   More structured

Useful during early IA design                                      Useful during IA validation

Reveals natural grouping patterns                                  Reveals category fit


Practical Example – Online Shopping App

Open Card Sorting:

Give users 20 product cards and ask them to create their own categories.

They might create:

     Electronics
     Home Appliances
     Personal Accessories

Closed Card Sorting:

Provide predefined categories:

     Electronics
     Fashion
     Home & Kitchen

Ask users to place each product into the appropriate category.


Interview Answer (English)

"Open Card Sorting allows users to create their own categories, helping us understand their mental models. Closed Card Sorting provides predefined
categories and asks users to organise content within them. I use open sorting during early information architecture exploration and closed sorting to
validate an existing categorisation system."




33. Hierarchical Navigation vs Flat Navigation

తెలుగు వివరణ
Hierarchical Navigation:

సమాచారాన్ని Parent Category, Subcategory, Sub-subcategory రూపంలో స్థా యిలవారీగా అమర్చడం.

ఉదాహరణ:

Electronics → Mobiles → Android Phones → Samsung.

Flat Navigation:

సమాచారాన్ని తక్కువ స్థా యిల్లో లేదా ఒకే స్థా యిలో ఉంచి, యూజర్లు నేరుగా అవసరమైన విభాగానికి వెళ్లేలా చేయడం.

English Definitions

     Hierarchical Navigation: A navigation model that organises content into parent-child relationships and multiple levels.
     Flat Navigation: A navigation model that minimises hierarchy by making major sections directly accessible from a common level.
Key Differences

Hierarchical Navigation                                      Flat Navigation

Multiple content levels                                      Fewer content levels

Uses parent-child relationships                              Provides direct access to sections

Suitable for large content structures                        Suitable for smaller structures

Can require deeper navigation                                Reduces navigation depth

Needs clear hierarchy                                        Needs careful grouping


Practical Example – E-commerce App

Hierarchical:

Home → Electronics → Mobiles → Android → Samsung.

Flat:

Home → Mobiles | Laptops | Tablets | Accessories.


Interview Answer (English)

"Hierarchical navigation organises information into multiple levels, making it suitable for products with large and complex content structures. Flat
navigation reduces the number of levels and provides quicker access to major sections. The right approach depends on content complexity, user needs
and navigation requirements."




34. Global Navigation vs Local Navigation

తెలుగు వివరణ
Global Navigation:

వెబ్‌సైట్ లేదా యాప్‌లోని అన్ని ప్రధాన విభాగాలకు వెళ్లడానికి ఉపయోగించే ప్రధాన Navigation System.

ఇది సాధారణంగా ప్రతి పేజీలో కనిపిస్తుంది.

Local Navigation:

ఒక నిర్దిష్ట విభాగం లేదా పేజీకి సంబంధించిన Subsections మధ్య ప్రయాణించడానికి ఉపయోగించే Navigation System.

English Definitions

     Global Navigation: A primary navigation system that provides access to the major sections of a website or application across the entire product.
     Local Navigation: A secondary navigation system that helps users navigate within a specific section or subsection.


Key Differences

Global Navigation                                        Local Navigation

Covers the entire product                                Covers a specific section

Provides primary access                                  Provides secondary access

Usually consistent across pages                          Changes based on current section

Main menu or primary tabs                                Submenu or section tabs

Helps users switch sections                              Helps users explore a section


Practical Example – D'SARAS Website

Global Navigation:

     Home
     About
     Design Services
     Design Acharya
     Animation Films
     Contact

Local Navigation:

Inside Design Acharya:

     Courses
     Curriculum
     Mentors
     Projects
     Admissions


Interview Answer (English)

"Global navigation provides access to the major sections of a product and remains relatively consistent across pages. Local navigation helps users
explore subsections within a particular area. Both work together to create a clear and predictable information architecture."




35. Breadcrumb Navigation vs Tab Navigation

తెలుగు వివరణ
Breadcrumb Navigation:

యూజర్ వెబ్‌సైట్‌లో ప్రస్తు తం ఏ పేజీలో ఉన్నాడు? ఆ పేజీకి ముందు ఉన్న Parent Pages ఏమిటి? అనే విషయాలను చూపించే Navigation Pattern.

ఇది ముఖ్యంగా Hierarchical Websites లో ఉపయోగపడుతుంది.

Tab Navigation:

ఒకే స్థా యి లేదా సంబంధిత కంటెంట్ విభాగాల మధ్య త్వరగా మారడానికి ఉపయోగించే Navigation Pattern.

English Definitions

     Breadcrumb Navigation: A secondary navigation pattern that shows the user's current location within a hierarchical structure and provides links to
     parent levels.
     Tab Navigation: A navigation pattern that allows users to switch between related content sections within the same context.


Key Differences

Breadcrumb Navigation                                   Tab Navigation

Shows location in hierarchy                             Switches between related sections

Parent-child navigation                                 Peer-level navigation

Helps users navigate backward                           Helps users switch content

Usually displayed as a path                             Usually displayed as tabs

Common in e-commerce websites                           Common in dashboards and apps


Practical Example – E-commerce Website

Breadcrumb:

Home → Electronics → Mobiles → Samsung Galaxy.

Tabs:

Product Details | Specifications | Reviews | FAQs.


Interview Answer (English)

"Breadcrumb navigation helps users understand their current position within a hierarchical website structure and navigate to parent pages. Tab
navigation allows users to switch between related content sections at the same level without leaving the current context."




36. User Flow vs Wireflow

తెలుగు వివరణ
User Flow:

యూజర్ ఒక లక్ష్యాన్ని చేరుకోవడానికి అనుసరించే స్క్రీన్లు , చర్యలు మరియు నిర్ణయాల క్రమాన్ని చూపిస్తుంది.

ఇది సాధారణంగా Flowchart Symbols, Boxes, Arrows మరియు Decision Nodes ఉపయోగించి రూపొందిస్తా రు.

Wireflow:

User Flow మరియు Wireframe రెండింటినీ కలిపిన Visual Representation.

ఇందులో కేవలం బాక్సులు మరియు బాణాలు కాకుండా, ప్రతి దశలో స్క్రీన్ ఎలా కనిపిస్తుంది? దానిలో ఏ UI Elements ఉంటాయి? అనే వివరాలు కూడా ఉంటాయి.

English Definitions

     User Flow: A diagram illustrating the sequence of screens, actions and decisions users follow to complete a goal.
     Wireflow: A combination of user flow diagrams and wireframes that illustrates both the navigation path and the basic screen layouts.


Key Differences

User Flow                                        Wireflow

Shows interaction paths                          Shows interaction paths and screen layouts

Uses flowchart elements                          Uses simplified wireframes and connectors

Focuses on navigation logic                      Focuses on navigation and interface structure

Less visual detail                               More visual detail

Helps understand overall flow                    Helps communicate screen-level flow


Practical Example – Mobile Login

User Flow:

Open App → Enter Mobile Number → Verify OTP → Login Successful.

Wireflow:

Shows the same sequence, but also includes:

     Mobile number input screen.
     OTP entry screen.
     Resend OTP button.
     Error message layout.
     Successful login screen.




                                                                                                         9




Interview Answer (English)

"User Flow focuses on the sequence of interactions and decision points users follow to complete a task. Wireflow combines this flow with simplified
wireframes, showing what each screen looks like along the journey. I use User Flows to define interaction logic and Wireflows to communicate that logic
alongside the interface structure."




37. Happy Path vs Edge Case

తెలుగు వివరణ
Happy Path:

ఒక వినియోగదారుడు ఎటువంటి సమస్యలు లేదా అంతరాయాలు లేకుండా తన పనిని విజయవంతంగా పూర్తి చేసే సాధారణ మార్గం.
Edge Case:

సాధారణంగా జరగని, అరుదుగా ఎదురయ్యే ప్రత్యేక పరిస్థితులు లేదా అసాధారణ పరిస్థితులను Edge Cases అంటారు.

UX Designer అన్ని వినియోగదారులు Happy Path లోనే ప్రయాణిస్తా రని అనుకోకూడదు. Error States, Network Issues, Empty States వంటి పరిస్థితులను కూడా డిజైన్
చేయాలి.

English Definitions

     Happy Path: The ideal sequence of interactions where a user completes a task successfully without errors or interruptions.
     Edge Case: An unusual or less common scenario that may occur under specific conditions and needs to be considered in product design.


Key Differences

Happy Path                                                 Edge Case

Ideal user scenario                                        Unusual or exceptional scenario

Assumes normal conditions                                  Handles unexpected conditions

Focuses on successful completion                           Focuses on robustness

Core workflow                                              Additional scenarios

Primary design requirement                                 Important supporting requirement


Practical Example – Banking App

Happy Path:

Login → Select Beneficiary → Enter Amount → Confirm → Money Transferred Successfully.

Edge Cases:

     Insufficient account balance.
     Incorrect OTP.
     Internet connection lost.
     Beneficiary account is inactive.
     Daily transaction limit exceeded.
     Bank server unavailable.


Interview Answer (English)

"The Happy Path represents the ideal scenario where users successfully complete a task without interruptions. Edge Cases represent unusual conditions
that can affect the experience. As a designer, I ensure that the primary workflow is simple while also designing meaningful error states and recovery
options for exceptional scenarios."




38. User Scenario vs Use Case

తెలుగు వివరణ
User Scenario:

ఒక వినియోగదారుడు ఒక నిర్దిష్ట పరిస్థితిలో ప్రొ డక్ట్‌ను ఎందుకు మరియు ఎలా ఉపయోగిస్తు న్నాడో కథనం రూపంలో వివరించడం.

ఇది User Context, Goals, Motivation మరియు Situation పై దృష్టి పెడుతుంది.

Use Case:

ఒక వినియోగదారుడు ఒక నిర్దిష్ట లక్ష్యాన్ని సాధించడానికి System తో ఎలా Interaction చేస్తా డు? System ఎలా స్పందిస్తుంది? అనే విషయాలను Structured Steps రూపంలో
వివరించడం.

English Definitions

     User Scenario: A narrative description of how a particular user interacts with a product in a specific situation to achieve a goal.
     Use Case: A structured description of interactions between an actor and a system to achieve a specific goal, including possible alternative and
     exception flows.


Key Differences
User Scenario                                      Use Case

Narrative-based                                    Structured and detailed

Explains context and motivation                    Explains system interactions

Focuses on user situation                          Focuses on user-system behaviour

Describes a possible experience                    Describes functional interaction

Useful for ideation and empathy                    Useful for requirements and system design


Practical Example – Food Delivery App

User Scenario:

"Ravi is returning home after work. He is tired and wants to order dinner quickly using a food delivery app."

Use Case: Order Food

     Actor: Customer.
     Precondition: User is logged in.
     Step 1: Search for a restaurant.
     Step 2: Select food items.
     Step 3: Add items to cart.
     Step 4: Enter delivery address.
     Step 5: Make payment.
     Step 6: Receive order confirmation.

Alternative: Payment fails, so the user selects another payment method.


Interview Answer (English)

"A user scenario describes the context, motivation and situation in which a user interacts with a product. A use case provides a more structured
description of the interactions between the user and the system to achieve a particular goal. Scenarios help us understand user context, while use cases
help define system behaviour."




39. Use Case vs User Story

తెలుగు వివరణ
Use Case:

ఒక వినియోగదారుడు ఒక లక్ష్యాన్ని సాధించడానికి సిస్టమ్‌తో ఎలా Interaction చేస్తా డు? ఆ సమయంలో సిస్టమ్ ఎలా స్పందిస్తుంది? అనే విషయాలను వివరంగా తెలియజేస్తుంది.

User Story:

Agile Product Development లో ఉపయోగించే చిన్న Requirement Statement.

ఇది వినియోగదారుడి దృష్టికోణం నుంచి ఒక ఫీచర్ ఎందుకు అవసరమో వివరిస్తుంది.

సాధారణంగా User Story ఈ Format లో ఉంటుంది:

"As a [User], I want [Goal], so that [Benefit]."


English Definitions

     Use Case: A structured description of interactions between an actor and a system, including main and alternative flows to achieve a goal.
     User Story: A concise requirement written from the user's perspective that describes a desired capability and its value.


Key Differences

Use Case                                               User Story

Detailed interaction description                       Short requirement statement

Describes system behaviour                             Describes user need and value

Includes main and alternative flows                    Usually supported by acceptance criteria

Useful for functional analysis                         Common in Agile development
More structured and detailed                                 Lightweight and flexible


Practical Example – Banking App

User Story:

"As a banking customer, I want to transfer money to saved beneficiaries so that I can complete transactions quickly."

Use Case: Money Transfer

     Actor: Banking Customer.
     Preconditions: Customer is logged in.
     Main Flow: Select beneficiary, enter amount, verify details, authenticate and transfer.
     Alternative Flow: Invalid OTP or insufficient balance.
     Postcondition: Transaction status is updated.


Interview Answer (English)

"A User Story is a concise description of a user need and the value they expect from a feature. A Use Case describes the detailed interactions between
the user and the system, including alternative scenarios. User Stories are commonly used in Agile backlogs, while Use Cases provide more detailed
functional understanding."




40. User Flow vs Screen Flow

తెలుగు వివరణ
User Flow:

యూజర్ ఒక లక్ష్యాన్ని సాధించడానికి తీసుకునే చర్యలు, నిర్ణయాలు మరియు వివిధ మార్గా లను వివరిస్తుంది.

ఇది User Behaviour మరియు Interaction Logic పై దృష్టి పెడుతుంది.

Screen Flow:

ఒక ప్రొ డక్ట్‌లో యూజర్ ఏ స్క్రీన్ నుంచి ఏ స్క్రీన్‌కు వెళ్తా డు? స్క్రీన్ల మధ్య క్రమం ఏమిటి? అనే విషయాలను చూపిస్తుంది.

ఇది ప్రధానంగా Screen-to-Screen Navigation పై దృష్టి పెడుతుంది.

English Definitions

     User Flow: A representation of the actions, decisions and alternative paths users follow to achieve a goal.
     Screen Flow: A representation of the sequence and relationships between screens within an application or digital product.


Key Differences

User Flow                                                                Screen Flow

Focuses on user actions and decisions                                    Focuses on screen sequence

Includes decision logic                                                  Shows screen transitions

Can include multiple paths                                               Maps screen relationships

User-behaviour oriented                                                  Interface-navigation oriented

Explains how users achieve goals                                         Explains how screens connect


Practical Example – Mobile Banking App

User Flow:

Open App → Login → Choose Transfer Type → Check Beneficiary → Transfer → Confirmation.

Screen Flow:


                                                                                    Splash Screen




                                                                                     Login Screen
                                                                             Dashboard




                                                                          Beneficiary Screen




                                                                           Transfer Screen




                                                                           Success Screen

                                                                  Illustrative screen sequence



Interview Answer (English)

"User Flow explains the user's actions, decisions and paths to achieve a goal, whereas Screen Flow focuses on the sequence and connections between
the actual application screens. User Flow defines the interaction logic, while Screen Flow helps organise the screen-level navigation."
